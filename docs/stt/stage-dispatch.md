# Стадии эпика на сервере

Этап 2 ТЗ `tz-conveyor-in-multica.md`. Сервер multica сам назначает скваду задачи следующей стадии эпика, когда
закрыты предыдущие; сторож для такого эпика не назначает.

## Включить и выключить

```sh
multica issue stages STT-239 --squad "Разработка"   # включить: стадии эпика идут скваду
multica issue stages STT-239                          # посмотреть
multica issue stages STT-239 --off                    # выключить
```

API: `GET/PUT /api/issues/{id}/stage-dispatch`, тело `{"squad_id": "<id>"}` или `{"squad_id": null}`. Включает только
человек (агенту — 403): раны, которые запустит назначение, отвечают ему. Нужно право будить лидера сквада.

## Правила

- Открытая стадия — первая по номеру, где есть задача не закрытая и не ждущая заказчика.
- Её задачи **без исполнителя** назначаются скваду сразу, все; задачи с исполнителем не трогаются. Задача из `backlog`
  переходит в `todo`. Назначение запускает маршрут сквада по умолчанию (этап 4 ТЗ моделей) или будит лидера —
  так же, как назначение человеком.
- Закрытой считается задача в статусе категорий «готово»/«закрыто» и задача, чей маршрут завершился через шаг
  `accept` (её коммит уже влит).
- Статус `waiting` («Ждёт заказчика», появляется в каталоге при включении) — задача ждёт ответа: её не назначают, и
  стадия, где открыты только такие задачи, следующие не держит. Заменяет «**Ждёт:**» в описании.
- Задачи без стадии сервер не назначает.
- Назначение идёт сразу после изменения подзадачи и раз в минуту проходом планировщика (`issue_stage_dispatch`) —
  он же подхватывает маршруты, влитые через `accept` (они не меняют статус задачи).
- Закрытие стадии такого эпика не будит исполнителя эпика (правило `child_done`): следующая стадия уже назначена.
  Закрытие всех подзадач будит, как раньше.

## Выкладка и откат

Миграции 587 (колонки `issue.stage_squad_id`, `issue.stage_dispatch_by`) и 588 (частичный индекс `CONCURRENTLY`),
обе аддитивные. Backend — пакетом `deploy/stt-models`. Откат: `multica issue stages <эпик> --off` — дальше назначает
сторож (`multica-conveyor` ≥ `server-stage-dispatch`); down-миграции удаляют индекс и колонки.
