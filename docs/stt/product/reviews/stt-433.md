## Визуальная проверка

Сравнение текущего продукта — по коду и сохранённым снимкам приёмки STT-424,
не по свежему production-сеансу:

- `runtimes-light-1440.png`: навигация, группировка машин, положение Add;
- `profile-editor-dark-375.png`: модальный редактор, поля, Select и нижние действия;
- перечень остальных источников — [ui.md](../ui.md) и
  [generated/screenshots.json](../generated/screenshots.json).

Подготовлен v6 существующего статического макета. В v5 личный режим фактически
переключался на общий, перестановка пула меняла сохранённый массив до Save,
поле spend не сохранялось, на 375 px колонки 4+ скрывались. В v6 эти состояния
поправлены; неизвестные аккаунты в аналитике видны отдельно; целевой порядок
Claude приведён к принятому решению. Это данные макета, не правка инстанса.

Проверяются обе темы × 1440/375: страницы, открытые диалоги лимита/входа/
добавления/профиля, личный режим, несохранённый пул, конфликт ревизии и участник
без прав. У длинного редактора строк прокручивается тело, действия доступны
внизу окна. У select собственный шеврон и правый padding 34 px.

Скриншоты, манифесты, проверки и исходники передаются вложением STT-439.
`v5 → v6` означает сравнение макетов; оно не выдаётся за реализованный продукт.
Китовые компоненты воспроизведены HTML/CSS; в разработке используются настоящие
Button/Dialog/Select и семантические токены. Действующие ru-ключи используются
для существующих надписей, новые согласованные подписи добавляются в локаль.

MCP stand у исполнителя недоступен. По резервному условию STT-439 артефакт v6
сохранён для последующего `art_publish` под именем существующего артефакта.
Пока публикации нет, [публичная ссылка](https://art-multica-kiss-v5-0da4e4.stand.yakutov.com)
показывает v5. Подключение MCP и разрешение вопроса о журнале остаются внешними
условиями завершения, не выполненной частью результата.

## Единственный вопрос по продукту

Для `subscription run` нужна история ручных запусков (аккаунт, начало/конец,
код завершения) либо только существующие замеры квоты после команды?
Рекомендуется история запусков, если важно доказуемо видеть работу человека
под аккаунтом. Это требует согласовать хранение и срок; квотные наблюдения
не доказывают, что команду запускал человек. До решения новая таблица не
проектируется. Этот выбор не следует ни из индекса, ни из текущего кода.
