# Регистрация раннеров РП: условия первого запуска

Евгений 26.10 в продолжении чата с Продактом поручил зарегистрировать раннер
приватного `inoisy/resource-planning`. Исполнение использует принятую схему
[STT-453](https://multica.yakutov.com/stt/issues/STT-453): `rp-ci` и `rp-ops`,
разные системные пользователи и каталоги, systemd, лимиты и хуки.
Повторного разрешения на регистрацию не требуется. Зеркало, слияние импорта
и переключение доставки не входят в это отдельное поручение.

## Проверено до запуска

- GitHub вернул `permissions.admin=true`; репозиторий остаётся private.
- Хост — Ubuntu 24.04, на `/` свободно 36 ГБ; `/opt/rp-runner` отсутствует.
- `ops/github-runner/` и `.node-version` рабочего main не отличаются от
  принятого SHA `9b0545bb1e78b573d856fe04d4753b56f84bb01c`.
- `sudo -n …/ops/github-runner/install.sh --repo-dir …/service` вернул
  `sudo: a password is required` до исполнения установщика.
  У рана нет общего root и допуска sudo для этого скрипта.
- Регистрационный токен не запрашивался; регистрации, системные установки,
  новые раны и переключения доставки не выполнялись.

## Дефект установщика

`install.sh` создаёт каталог `tmp_r` через `mktemp -d` под root (0700),
затем выполняет `runuser -u rp-<inst> -- tar -xzf <путь внутри tmp_r>`.
Пользователь раннера не может пройти в этот каталог и открыть архив.
Это вывод из кода и режима доступа, не результат реальной root-установки.

Адресная правка существующего скрипта, которую нужно передать в review:

```diff
-    runuser -u "rp-$inst" -- tar -xzf "$tmp_r/$archive_runner" -C "$dir"; rm -rf "$tmp_r"
+    runuser -u "rp-$inst" -- tar -xzf - -C "$dir" < "$tmp_r/$archive_runner"; rm -rf "$tmp_r"
```

Root открывает проверенный архив перенаправлением до смены пользователя;
распаковка остаётся от имени пользователя раннера. Доступ к временному
каталогу расширять не требуется. Продакт код установщика не менял.

## Остаток для исполнения

После адресной правки и review оператор root запускает существующий установщик
с `RP_RUNNER_TOKEN` по `docs/github-ci.md` репозитория РП. Токен выдаётся перед
запуском, живёт час и не публикуется в отчётах. Прежнее разрешение Евгения
сохраняется; препятствие — права процесса и дефект скрипта, а не отсутствие
согласия автора.

Критерий регистрации: обе записи в GitHub `online`, службы `rp-runner@ci`
и `rp-runner@ops` активны с принятыми пользователями и ограничениями.
Для отката существуют `ops/github-runner/rollback.sh stop` и `unregister`.
Пользовательский раннер без согласованной изоляции не заменяет установку.

Описание STT-453 дополнено с `--no-start`; новые исполнители не запускались.
Старый статус done подтверждает локальное слияние кода, регистрация им не доказана.


## Исправление тихого выхода операционного скрипта

После сообщения Евгения о пустом выводе подтверждён ещё один дефект запуска:
в системном PATH отсутствует gh, а первая версия операционного скрипта
выполняла `command -v gh >/dev/null` под `set -e`. Она завершалась без вывода
до создания каталогов установки. Это ошибка подготовленного Продактом скрипта.

Обновлён `/home/agents/resource-planning/register-rp-runners.sh`: GitHub CLI
вызывается по абсолютному пути, из root-сессии GitHub и git выполняются через
runuser от agents, системные действия остаются root. Добавлены этапы, явные
ошибки и режим `--check`, не выполняющий установку и не выпускающий токен.
Проверка с пустым окружением и системным PATH успешно подтвердила доступ к
приватному репозиторию, принятому SHA, Ubuntu 24.04 и 36 ГБ свободного места.
`bash -n` проходит; реальный запуск из root-сессии этой проверкой не подтверждён.
Обновлённый скрипт приложен в чат и заменён по прежнему постоянному пути.


## Результат root-запуска, 17:51 UTC

После сообщения Евгения о выполнении установки проверены GitHub и systemd:

- `rp-ci-marcelle` и `rp-ops-marcelle` зарегистрированы, оба `online`, метки
  соответствуют CI и ops. Повторная регистрация не нужна.
- `rp-runner@ci` и `rp-runner@ops` — `active/running` с 17:51:16 и 17:51:21 UTC.
  Раздельные пользователи, `ProtectHome=yes`, `ProtectSystem=strict`,
  `NoNewPrivileges=yes` применены. CI: CPU 300%, RAM 6 ГБ; ops: CPU 50%, RAM 512 МБ.
- На `/` свободно 34 ГБ, занято 78%.

Первый [CI на собственном раннере](https://github.com/inoisy/resource-planning/actions/runs/40340441758/job/121633379487)
запустился на `rp-ci-marcelle`, но завершился FAILURE до выполнения тестов.
После job-started checkout и даже `/usr/bin/bash` завершающего хука не могут
запуститься с рабочим каталогом
`/opt/rp-runner/ci/_work/resource-planning/resource-planning`:
`No such file or directory`.

Причина подтверждена изолированным воспроизведением без root: в одноразовом
каталоге создан workspace, существующий `job-started.sh` запущен с соответствующими
`RP_RUNNER_DIR`, `GITHUB_WORKSPACE` и ролью ci. Хук вернул 0, но удалил workspace.
Его find очищает весь `_work`, включая уже подготовленный рабочий каталог.
Живые каталоги и хуки при этом не менялись.

Адресное продолжение — исправить существующий хук так, чтобы очистка сохраняла
сам рабочий каталог и cwd, проверить регрессию и прежние проверки ops/диска,
затем review и поддерживаемая root-установка хука. После исправления достаточно
одного повтора упавшего CI. Перезапуск до изменения причины не нужен.

Описание STT-453 дополнено с `--no-start` (ревизия 41). Новые раны, перезапуск
CI, изменения данных или доставки не выполнялись. Регистрация раннеров готова;
зелёный CI и весь переход на новую доставку остаются неподтверждёнными.
