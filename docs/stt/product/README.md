## Зачем продукт

Multica соединяет задачу, человека, агента, выполнение на своей машине и результат
в одном workspace. Работа назначается агенту на доске; инструкции, обсуждение,
запуск и проверяемый результат остаются связаны с задачей. Основание:
[README репозитория](../../../README.md), [VISION](../../../VISION.md).

Для нашего форка ближайшая цель — убрать ручную координацию выбора моделей,
аккаунтов и маршрутов. Сервер выбирает модель из профиля, демон подтверждает
аккаунт, Project Workflow сохраняет порядок шагов и принятый коммит.
Источники: [STT-420](https://multica.yakutov.com/stt/issues/STT-420),
[STT-429](https://multica.yakutov.com/stt/issues/STT-429),
[модель выбора](../../../server/internal/service/model_choice.go),
[Workflow](../../../server/internal/issueworkflow/issueworkflow.go).

## Проверка актуальности

Из корня репозитория:

```sh
git fetch origin main
python3 tools/product/index.py check
python3 tools/product/index.py build
python3 tools/product/index.py find runtime_id --kind query --limit 10
python3 tools/product/index.py screens /api/pools
python3 tools/product/index.py trace listPools
```

`check` и поиск отказывают при несовпадении SHA с `origin/main` или
отпечатка индексируемых файлов с рабочей копией. SHA относится к продуктовому
срезу; добавление документации и инструментов поверх него не меняет этот SHA.
Для другой ветки явно передавать `--ref HEAD`. Подробности:
[tools/product/README.md](../../../tools/product/README.md).

## Как понять, что текущие доработки достигли цели

Не новые KPI, а проверяемые критерии уже поставленных задач: изменение общего
профиля доходит до использующих его агентов; инспектор согласован со строкой 1;
пул управляется в одном месте; неизвестный аккаунт запуска не подменяется догадкой;
переход Workflow сохраняет принятый SHA. Источники: критерии
[STT-433](https://multica.yakutov.com/stt/issues/STT-433),
[контракт факта запуска](../../engineering/model-accounts-server-api.md),
[Workflow API](../../../server/internal/handler/issue_workflow.go).

Все внутренние данные базы остаются в `docs/stt/`. В апстрим переносится только
обезличенная спецификация после согласования, по
[STT-435](https://multica.yakutov.com/stt/issues/STT-435).
