Скрипт выкатки переноса подписок в аналитику и исправлений адаптива сред выполнения.
Исходники зафиксированы полным SHA в `deploy.sh`; задачи в Сфере нет, используется T-12345.

Запускать от root на сервере Multica. Действующая установка: `/opt/multica/docker-compose.selfhost.yml`,
клон форка `/root/multica-ru`, сборщик `stand-build`, backend `aebbec787` из v0.7.0.

```bash
sudo bash deploy-multica-analytics.sh --check
sudo bash deploy-multica-analytics.sh
```

Если скрипт запускается из репозитория, его имя — `deploy/analytics-web/deploy.sh`.
`--check` проверяет проект, сервисы, здоровье, сборщик и коммит. Он скачивает проверенный коммит в Git-кэш,
но не собирает и не меняет образы, контейнеры или конфигурацию. При отсутствии подходящего backend
проверка остановится до выкатки. Для другого проверенного backend его SHA-приставку можно передать
через `EXPECTED_BACKEND_COMMIT`; это решение оператора после проверки совместимости.

При выкатке скрипт собирает только `Dockerfile.web`, сохраняет прежний образ отдельным тегом и заменяет
только `frontend`/`web` с `--no-deps --no-build --pull never`. Существующий тег веба сохраняется, поэтому
обычный последующий Compose up использует установленную версию. Все действующие Compose overrides
берутся из меток продового backend. `.env`, настройки reverse proxy, `/pages-api/`, БД, backend
и демон сохраняются. Миграций в этой правке нет.

До и после проверяются идентификаторы и время старта остальных контейнеров, а также PID демона.
При отказе нового веба скрипт автоматически возвращает прежний образ и завершается с ошибкой.
Бэкап, `build.log`, `state.env` и команда ручного отката остаются в напечатанном каталоге:

```bash
sudo bash /var/backups/multica-web-analytics.XXXXXXXX/rollback.sh
```

Откат отказывается заменять образ, если после этой выкатки уже установлен другой релиз.
Параллельные запуски блокируются `flock`. Старые образы автоматически не удаляются.

Параметры существующей установки можно передать через `FORK`, `COMPOSE`, `BUILDER`, `API`, `WEB`,
`DAEMON_UNIT`. При наличии в одном проекте и `frontend`, и `web` требуется явно выбрать `WEB_SERVICE`.

Проверки без доступа к продовым Docker и БД:

```bash
bash -n deploy/analytics-web/deploy.sh
python3 -I -m unittest discover -s deploy/analytics-web -p test_deploy.py -v
```

Тесты покрывают выбор конкретного Compose-проекта, проверку без изменений, выкатку и ручной откат,
автооткат при отказе здоровья, отказ сборки, несовместимый backend, изменение стека во время сборки
и запрет отката поверх более нового релиза. Реальную выкатку выполняет оператор.
